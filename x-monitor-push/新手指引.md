# 🐣 保姆级操作指引（零基础版）

> 目标：让 3 个 X 账号的动态每天自动抓取、每周一自动推送到你的企业微信群。
> 你**不需要懂编程**，照着下面一步步点就行。全程大概 40~60 分钟（大部分时间花在注册账号上）。

---

## 📋 开始前你要知道的

这套系统靠 4 样东西运转，我们要先把它们的「钥匙」准备好，最后填到工蜂的蓝盾里：

| 要准备的钥匙 | 干什么用的 | 花钱吗 |
|---|---|---|
| ① TwitterAPI.io 的 Key | 用来抓 X 推文 | 每月几毛钱 |
| ② DeepSeek 的 Key | 把英文翻译成中文、写周报分析 | 每月一两块钱 |
| ③ 企业微信机器人 Webhook | 把周报发到你的群 | 免费 |
| ④ 工蜂 Access Token | 让程序能把数据存回仓库 | 免费 |

> 💡 建议：把这 4 个钥匙**边拿边记到一个记事本里**，最后一次性填进去。

---

# 阶段一：拿 TwitterAPI.io 的 Key（抓推文用）

1. 打开浏览器，访问 **https://twitterapi.io**
2. 点右上角 **Sign in / Get Started**，用 **Google 账号一键登录**（不需要申请、不需要审核）
3. 登录后进入控制台（Dashboard），左侧找 **API Keys**
4. 页面上会有一串 `xxxxxxxx...` 的字符，这就是你的 Key —— **复制下来，记到记事本，标注①**
5. 新用户送 $1 免费额度，够你先跑起来验证。以后充值几美元能用很久。

✅ **完成标志**：记事本里有了 ① 一串 Key。

---

# 阶段二：拿 DeepSeek 的 Key（翻译+分析用）

1. 访问 **https://platform.deepseek.com**
2. 注册 / 登录（手机号即可）
3. 左侧菜单找 **API Keys（API 密钥）** → 点 **创建 API Key**
4. 给它起个名字（随便，比如 `x-monitor`）→ 创建后**立刻复制**那串 `sk-xxxx`
   - ⚠️ 这串只显示一次，关掉就看不到了，一定当场复制！记到记事本，标注②
5. 充值：进「充值」页充个 10 块钱，能用好几个月。

✅ **完成标志**：记事本里有了 ② `sk-` 开头的 Key。

> 不想用 AI 翻译也行（跳过本阶段），那样周报会直接给英文原文汇总。但强烈建议配上，体验差很多。

---

# 阶段三：建企业微信群机器人（收周报用）

1. 打开**企业微信**，进入（或新建）一个用来接收周报的群
   - 小技巧：可以建一个只有你自己的群，专门当"通知箱"
2. 点群右上角 **···** → **群机器人** → **添加机器人** → 起个名字如「X监控」→ 确定
3. 添加后点开这个机器人 → **复制 Webhook 地址**
   - 长这样：`https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx`
   - 复制下来，记到记事本，标注③

✅ **完成标志**：记事本里有了 ③ 一条 `https://qyapi.weixin.qq.com/...` 地址。

# 阶段四：把项目代码放进工蜂仓库

### 4.1 新建仓库
1. 访问 **https://git.woa.com**（内网工蜂），用企业账号登录
2. 右上角 **+** → **新建项目/仓库** → 名字填 `x-monitor` → 创建
3. 建好后你会看到仓库地址，形如 `https://git.woa.com/你的名字/x-monitor.git` —— **记到记事本，标注⑤（仓库地址）**

### 4.2 拿工蜂 Access Token（让程序能写回数据）
1. 工蜂右上角头像 → **设置 / Settings** → **访问令牌 / Access Tokens**
2. 新建令牌：名字填 `x-monitor`，权限**勾选 `api` 或 `write_repository`（读写仓库）**
3. 创建后**立刻复制**那串 token —— 记到记事本，标注④
   - ⚠️ 同样只显示一次！

### 4.3 上传代码（二选一）

**方式 A：网页直接上传（最适合小白）**
1. 进入刚建的空仓库，点 **上传文件 / Upload**
2. 把这个文件夹里的所有内容拖进去上传：
   ```
   C:\Users\wrenwszhang\WorkBuddy\2026-07-22-18-05-30
   ```
   包含 `scripts/`、`templates/`、`config/`、`README.md` 等（`.workbuddy` 那种隐藏文件夹不用传）
3. 提交（Commit）

> 如果网页不支持整个文件夹拖拽，就一个文件夹一个文件夹地传，或者让我帮你打个压缩包。

**方式 B：用 Git 命令（会一点命令行的话）**
在项目文件夹里打开终端，依次运行（把地址换成你的⑤）：
```bash
git init
git add .
git commit -m "init x-monitor"
git remote add origin https://git.woa.com/你的名字/x-monitor.git
git push -u origin master
```

✅ **完成标志**：在工蜂网页上能看到 `scripts`、`config` 等文件夹。

# 阶段五：在蓝盾配置定时任务（核心，跟着点就行）

蓝盾是腾讯内部的自动化平台。我们要建 **2 条流水线**：一条每天抓、一条每周一推。

### 5.1 进入蓝盾，关联仓库
1. 访问蓝盾（内网搜「蓝盾」或 **devops.woa.com** 一类入口，具体域名以公司内网为准）
2. 新建项目（或用已有项目）
3. 左侧 **代码库** → **关联代码库** → 选你刚建的工蜂 `x-monitor`

### 5.2 建第一条流水线：日报（每天抓取）
1. 左侧 **流水线** → **新建流水线** → 选 **空白流水线** → 命名 `X监控-日报`
2. **设置定时**：点最上面的 **Trigger** → 添加 **定时触发** → cron 填：
   ```
   0 6 * * *
   ```
   （表示每天早上 6 点跑一次。如果发现时间不对，见下面「时区提示」）
3. **加变量**：还在 Trigger 页，找「流水线变量」，逐条添加（值填你记事本里的，敏感的勾选"敏感信息"）：

   | 变量名（照抄） | 值填 |
   |---|---|
   | `TWITTERAPI_IO_KEY` | ① |
   | `LLM_API_KEY` | ② |
   | `WECHAT_WEBHOOK_URL` | ③ |
   | `GIT_TOKEN` | ④ |
   | `GIT_REPO` | `git.woa.com/你的名字/x-monitor.git`（去掉开头 https://） |

4. **加执行步骤**：
   - 点 **添加 Stage** → 里面 **添加 Job** → 类型选 **Linux（Docker 公共构建机）**，镜像用默认
   - 在 Job 里 **添加插件** → 选 **代码拉取**，关联 `x-monitor` 仓库
   - 再 **添加插件** → 选 **Shell / 执行 Linux 脚本**，把下面这段**整段粘贴进去**：

```bash
set -e
python3 -m pip install --quiet requests jinja2

export TWITTERAPI_IO_KEY="${TWITTERAPI_IO_KEY}"
export WECHAT_WEBHOOK_URL="${WECHAT_WEBHOOK_URL}"
export LLM_API_KEY="${LLM_API_KEY}"
export LLM_API_BASE="https://api.deepseek.com"
export LLM_MODEL="deepseek-chat"

cd scripts
python3 run_daily.py

cd ..
git config user.name "bkci-bot"
git config user.email "bkci-bot@woa.com"
git add data docs
if git diff --staged --quiet; then
  echo "今天无变更"
else
  git commit -m "update $(date +%Y-%m-%d)"
  git push "https://oauth2:${GIT_TOKEN}@${GIT_REPO}" HEAD:master
fi
```

5. **保存**流水线。
6. **先手动试跑一次**：点 **执行**。等它跑完，点开 Shell 步骤看日志：
   - 看到 `已渲染看板` = 抓取成功 ✅
   - 回工蜂仓库看 `docs/index.html` 有没有生成 = 存档成功 ✅

### 5.3 建第二条流水线：周报（每周一推送）
最省事的办法：在流水线列表里找到 `X监控-日报`，点 **复制**，然后改 3 个地方：
1. 名字改成 `X监控-周报`
2. 定时 cron 改成：`0 7 * * 1`（每周一早 7 点）
3. Shell 脚本里，把 `python3 run_daily.py` 这一行改成 `python3 run_weekly.py`

保存后**手动执行一次** → 你的企业微信群应该收到一条周报消息 ✅（首次内容可能少，因为数据才刚开始攒）。

## ⏰ 时区提示（重要）

蓝盾定时用的是**服务器时间**，多数是北京时间。上面给的 `0 6 * * *`（每天 6 点）、`0 7 * * 1`（周一 7 点）都是按北京时间写的，一般直接能用。

**验证方法**：第一次配好后，把 cron 临时改成"5 分钟后"的时间（比如现在 15:25，就填 `30 15 * * *`），看它到点跑不跑，跑了说明时区对，再改回正式时间。

## 🆘 出问题了看这里

| 现象 | 原因 & 解决 |
|---|---|
| 日志报 `git push 403/401` | ④ 的 token 权限不够，重新生成时勾上"读写仓库" |
| 日志报 `python3: not found` | 换一个带 Python 的构建镜像，或问 CI 管理员 |
| 抓到 0 条 | 首次运行是"建基线"，第二天起才有新增；或那几个账号近 24 小时确实没发 |
| 企微没收到周报 | 检查 ③ webhook 是否填对、机器人还在不在群里；注意只有**周报**推送，日报不推 |
| 定时不跑 | 确认流水线已保存并启用；确认时区（见上） |
