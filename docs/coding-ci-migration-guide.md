## 1. 网站托管 — 开通 EdgeOne Makers + 拿到部署密钥

### 1.1 这一步在做什么（小白也能懂的解释）
你现在的网站是"放在 GitHub 提供的一个免费网络空间里"，别人访问 `nebula.stock-dashboard.com` 时其实是在访问 GitHub 的服务器。迁移后，我们换成用腾讯云的 **EdgeOne Makers**（一个类似的免费网络空间服务）来存放网站文件。因为它不能直接"盯着"工蜂仓库自动更新，所以我们用官方提供的一个小工具（CLI），让电脑/服务器主动把文件"发送"给它。

### 1.2 详细步骤

**第 1 步：注册/登录腾讯云账号**
1. 打开浏览器，访问：`https://console.cloud.tencent.com/edgeone/pages`
2. 如果你已经有腾讯云账号（QQ/微信/手机号都可以登录），直接登录即可；没有的话按提示注册一个（免费）。

**第 2 步：进入 Makers 控制台**
1. 登录后进入的页面如果显示"场景选择"或类似首页，找到 **Makers** 或 **Pages** 的入口点进去（页面可能会显示"立即开通"按钮，点一下）。
2. 如果页面顶部有多个 Tab（如"边缘安全加速""Makers"等），点击 **Makers** 这个 Tab。

**第 3 步：创建一个"直接上传"类型的项目（不要选"导入 Git 仓库"，因为它不支持工蜂）**
1. 点击「新建项目」。
2. 选择 **「直接上传」**（不是"导入 Git 仓库"，那个只支持 GitHub/Gitee 等，工蜂用不了）。
3. 填写项目名称，建议就叫 `korea-stock-dashboard`（后面配置要用到这个名字，记下来）。
4. 选择"加速区域"：如果你的域名已经在国内备案过，选"中国大陆"区域即可；如果没有备案，可以先选"全球"或"海外"区域（具体以控制台实际选项为准，不确定就选默认值，后续可以在项目设置里调整）。
5. 页面会提示你上传一个文件夹或 ZIP 包 —— **先不用上传**，这一步只是为了创建出这个项目壳子，后面会用命令行工具自动帮你上传，你可以先随便上传一个空文件夹/任意文件让项目创建成功（或者看看是否有"跳过，稍后通过 CLI 部署"的选项）。

> 如果这一步找不到"跳过"选项，也可以先把 `C:/Users/wrenwszhang` 整个项目文件夹（排除 `.git`、`node_modules` 等大文件夹，只留 `index.html`、`data/`、`CNAME` 等静态文件）压缩成 ZIP 包，直接在这里上传一次，把项目创建出来即可，后续的自动更新会由 CLI 命令覆盖它。

**第 4 步：生成 API Token（这是最关键的一步，用于让脚本有权限帮你部署）**
1. 在 Makers 控制台里找到「API Token」相关设置入口（通常在"账号设置"或项目设置的某个菜单里，不同版本 UI 位置可能略有差异，找不到的话搜索页面内"Token"关键字）。
2. 点击"新建/生成 Token"，生成后**立即复制保存**（这类密钥通常只显示一次，关闭弹窗后就看不到了）。
3. 把这个 Token 先粘贴到一个你自己的备忘录/密码管理工具里，暂时不要发给任何人，第 4 章我们会把它配置到工蜂流水线的"密钥"里。

**第 5 步（可选，强烈建议做一次）：在自己电脑上本地测试部署一次，确认 Token 能用**

打开命令行工具（Windows 上是 PowerShell），依次执行：

```powershell
# 1. 安装 EdgeOne 命令行工具（只需要装一次）
npm install -g edgeone

# 2. 进入项目目录（就是你现在这个看板项目的根目录）
cd C:\Users\wrenwszhang

# 3. 试着手动部署一次，把 <你的Token> 换成第4步复制的Token
edgeone makers deploy . -n korea-stock-dashboard -t <你的Token>
```

如果命令执行后提示部署成功，并给出一个预览网址，打开这个网址能看到你的看板页面，说明 Token 和项目名都配置对了，**记下这个项目名（`korea-stock-dashboard`）和 Token**，第 4 章会用到。

**第 6 步：绑定自定义域名（先用临时域名测试，不要立即动原域名）**
1. 在项目的「域名管理」里添加一个域名。
2. **强烈建议**：先添加一个临时的测试子域名（比如 `nebula-eop.stock-dashboard.com`），而不是直接把正式域名 `nebula.stock-dashboard.com` 切过来。
3. 按照页面提示，去你域名的 DNS 服务商（管理这个域名的地方，比如腾讯云DNSPod/万网等）添加一条 CNAME 记录，指向 EdgeOne 给你的目标地址。
4. 等待几分钟到几小时（DNS 生效有延迟），访问这个临时域名确认网站能正常打开。
5. 正式切换域名的操作放到第 6 章"确认无误后"再做。

## 2. 定时任务 — 工蜂 CI 新建流水线

### 2.1 这一步在做什么
原来 GitHub 每天凌晨会自动帮你跑一遍"抓数据、发通知"的脚本。现在要在工蜂上配置一个一样的"定时自动跑脚本"的功能，工蜂把这个功能叫做「流水线」（CI/CD Pipeline）。

### 2.2 详细步骤

**第 1 步：进入工蜂项目**
1. 打开浏览器，登录工蜂：`https://git.woa.com`
2. 进入你的项目 `wrenwszhang/korea-stock-dashboard`

**第 2 步：找到"流水线"或"持续集成"功能**
1. 在项目左侧菜单栏，找到「流水线」/「持续集成」/「CI/CD」相关入口（不同工蜂版本命名可能不同，通常在左侧导航栏中部）。
2. 如果这是你第一次使用，可能会提示"开通持续集成服务"，点击开通（一般免费额度足够这种轻量任务使用）。

**第 3 步：新建流水线**
1. 点击「新建流水线」按钮。
2. 流水线名称填：`每日股价数据更新`
3. 选择代码库：选你当前这个仓库 `korea-stock-dashboard`，分支选 `main`
4. 配置文件生成方式：选择 **「UI 配置流水线」**（图形化点选，不用自己写 YAML/配置文件，对新手最友好）。

**第 4 步：添加构建步骤（按顺序添加以下几个插件/步骤）**

| 顺序 | 步骤名称 | 具体配置 |
|---|---|---|
| 1 | 拉取代码 | 分支填 `main`（这一步通常系统会自动帮你加好，检查一下即可） |
| 2 | Node.js 环境 | 版本选择 `18` 或 `20`（在下拉框里选择，如果只有具体版本号选项，选 18.x 或 20.x 的最新小版本即可） |
| 3 | 执行 Shell 命令 | 命令框里填一行：`node scripts/ci-daily-update.mjs` |

> 如果找不到"执行 Shell 命令"这个插件名字，找一下类似"命令行执行""Shell 脚本""执行脚本"这样命名的插件，作用都是一样的：在服务器上跑一行命令。

5. 保存这条流水线。

### 2.3 配置定时触发（每天自动跑一次）

1. 在这条流水线的设置里，找到「触发方式」或「触发规则」。
2. 找到「定时触发」这个选项，点击"添加"。
3. 工蜂的定时触发一般是"图形化选择"，不需要输入 cron 表达式：
   - 日期：勾选"周一到周五"（跟股市开盘时间对应，周末不用跑）
   - 时间：设置为北京时间 **09:00**（对应原来 GitHub 那边的 UTC 01:00，即韩国股市开盘前，确保数据能及时更新）
4. 保存。

> 如果你想跑第二次（比如收盘后再确认一次数据），可以再加一条定时规则，时间设为北京时间 **17:00**（对应韩国股市 KST 18:00 左右，收盘后）。这个是可选的，不加也不影响基本功能。

### 2.4 Git 提交身份说明（不需要你手动配置，脚本已经处理好）
脚本 `ci-daily-update.mjs` 提交代码时默认使用邮箱 `wrenwszhang@tencent.com`（就是你工蜂账号绑定的邮箱），这样不会被工蜂的"身份校验"拒绝。你不需要额外操作。

## 3. 关于"定时触发时间"的换算参考表

| 用途 | 原 GitHub UTC 时间 | 换算成北京时间 (CST) |
|---|---|---|
| 每日数据更新 | 01:00 | 09:00 |
| 备用/补抓 | 01:30 | 09:30 |
| 收盘后二次确认 | 23:55（前一天） | 07:55 |

工蜂流水线的定时触发界面是"图形化点选"，不需要你计算或输入 cron 表达式，直接选北京时间的时间点即可，上面第 2.3 节已经给出建议值。

## 4. 密钥管理 — 在工蜂流水线里配置密钥

### 4.1 这一步在做什么
你的脚本运行时需要用到几个"密码"（比如企业微信推送地址、EdgeOne 的部署密钥），这些不能直接写在代码里（会泄露），需要配置在工蜂流水线的"变量"功能里，运行时自动注入进去，别人看不到明文。

### 4.2 详细步骤

1. 进入刚创建的流水线 → 找到「设置」或「变量」菜单（有些版本叫"环境变量""流水线变量"）。
2. 依次新增下面表格里的每一项。**"是否加密"一列标"是"的，一定要勾选"加密/敏感"类型**（一般是变量类型下拉框里选"密文"或勾选一个"加密"开关）：

| 变量名（Key） | 变量值（Value） | 是否加密 | 从哪里获取 |
|---|---|---|---|
| `EDGEONE_API_TOKEN` | 第1章第4步复制的 Token | **是** | 第1章第4步 |
| `EDGEONE_PROJECT_NAME` | `korea-stock-dashboard` | 否 | 第1章第3步你填的项目名 |
| `WECOM_WEBHOOK_URL` | 企业微信群机器人的 Webhook 地址（如果之前 GitHub Secrets 里配过，去 GitHub 仓库 Settings → Secrets 里看不到明文，需要重新在企业微信群里生成一个新的机器人 Webhook） | **是** | 企业微信群 → 群设置 → 群机器人 → 添加机器人，复制 Webhook 地址 |
| `DASHBOARD_URL` | `https://nebula.stock-dashboard.com`（迁移完成前先填临时测试域名） | 否 | 手动填写 |
| `OPENAI_API_KEY` | 你的 OpenAI API Key（可选，没有可以不填，脚本会自动降级为本地翻译） | **是** | 如果之前配置过就复用，没有可跳过 |

3. 全部添加完成后保存。

> 💡 **重新生成企微 Webhook 的小提示**：如果你不确定原来的 Webhook 地址是什么（GitHub Secrets 是加密存储，添加后无法查看明文），最简单的办法是打开对应的企业微信群 → 群设置 → 群机器人 → 找到现有机器人查看/重新生成 Webhook Key，或者直接新增一个机器人，用新的 Webhook 地址即可，两边（GitHub 和工蜂）可以先都配一样的地址，互不影响。

## 5. 并行验证 Checklist（重要，不要跳过这一步）

配置完成后，先**手动点一次"立即执行"**（流水线页面通常有个"运行"按钮），看看整个流程能不能跑通。然后让工蜂 CI 与 GitHub Actions **并行运行 3-5 个工作日**，每天核对：

- [ ] 工蜂流水线每天按时自动触发成功（进入流水线的"执行历史"查看，绿色表示成功）
- [ ] 打开工蜂仓库的 `data/latest.json`，日期和 GitHub 仓库里的是否一致
- [ ] 打开第1章第6步绑定的临时测试域名，看看股价数字、页面展示是否和正式站点一致
- [ ] 企业微信群每天只收到 1 次推送，没有重复或缺失
- [ ] 打开工蜂流水线的执行日志，看有没有红色的报错信息，尤其确认 `validate-data.mjs` 那一步是"通过"

如果发现任何不一致，先不要动 GitHub 那一边，把工蜂侧的日志截图记录下来，找我一起排查。

## 6. 停用 GitHub（确认工蜂侧稳定运行后才做这一步）

1. 把 `.github/workflows/daily-update.yml` 和 `deploy-pages-only.yml` 重命名（比如加个 `.disabled` 后缀），先不要直接删除，方便万一有问题时快速恢复。
2. 域名正式切换：去 DNS 服务商后台，把 `nebula.stock-dashboard.com` 的 CNAME 记录，从指向 GitHub Pages 的地址，改成指向 EdgeOne Makers 给你的目标地址（第1章第6步获取的）。
3. 把工蜂流水线里的 `DASHBOARD_URL` 变量值，从临时测试域名改成正式域名 `https://nebula.stock-dashboard.com`。
4. 去 GitHub 仓库的 Settings → Pages，把 Source 改成"None"关闭 GitHub Pages。
5. 观察 1-2 天，确认网站访问正常、数据每天正常更新、企微推送正常，迁移正式完成。
